# === ALL-IN-ONE: baseline + low + high + distributed attack, x3 seeds ===
# Run with: ./one.sh -b 12 default_settings.txt CCN_scenario_ALL.txt   (Windows: one.bat -b 12 ...)
#
# How this works: Scenario.attackProfile, Scenario.nrofHostGroups,
# InterestFlooder.interval, InterestFlooder.numOfMsgToGenerate, and
# Group13.nrofHosts are all 4-element arrays (baseline;low;high;distributed),
# so run index i picks column (i % 4). MovementModel.rngSeed is a
# 3-element array [13;27;41], so run index i picks (i % 3). Since 4 and 3
# share no common factor, running exactly 12 times visits every one of
# the 4 profiles x 3 seeds combinations exactly once - no repeats, no
# gaps. Each run gets its own report files because Scenario.name embeds
# both %%Scenario.attackProfile%% and %%MovementModel.rngSeed%%.
#
# Run index -> (profile, seed) mapping produced by -b 12:
#   0: baseline/13   1: low/27        2: high/41       3: distributed/13
#   4: baseline/27   5: low/41        6: high/13       7: distributed/27
#   8: baseline/41   9: low/13       10: high/27      11: distributed/41
#
# For the baseline runs, Group13 is simply never instantiated (only
# Group1..Group{nrofHostGroups} get created), so InterestFlooder.interval /
# numOfMsgToGenerate / Group13.nrofHosts at column 0 are never read - their
# baseline-column values below are placeholders and don't affect anything.
