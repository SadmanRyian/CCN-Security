# CCN-Security (CC-NDA)
### Content-Centric Networking Denial-of-Service & Poisoning Defense in Delay-Tolerant Networks

CCN-Security is an extended research fork of **The ONE (Opportunistic Network Environment)** simulator. It implements Content-Centric Networking (CCN) / Named Data Networking (NDN) paradigms over opportunistic/delay-tolerant wireless mobile networks (DTNs), models sophisticated denial-of-service and integrity attacks, and evaluates a **BPSec-inspired (Bundle Protocol Security) HMAC-SHA256 authentication and anti-replay defense framework**.

---

## Architecture Overview

```
                      +-----------------------------------+
                      |      CCN Node Architecture        |
                      |                                   |
    [Interest In] --->|  [PIT: Pending Interest Table]    |---> Forward Interest
                      |  - Tracks matching pending queries|     (Epidemic Routing)
                      |                                   |
                      |  [Content Store / Caching]        |
                      |  - Static Cache (Pre-seeded)      |
                      |  - Opportunistic Cache (LRU)      |
                      |                                   |
    [Data In] ------->|  [CCNSecurity Engine]             |---> Forward Data
                      |  - HMAC-SHA256 Tag Verification   |     (Spray-and-Wait)
                      |  - Anti-Replay / Freshness Check  |
                      |  - Policy Enforcement (Drop/Log)  |
                      +-----------------------------------+
```

### Core Communication Model
1. **Interest Packets (`query_ad`)**: Generated by Consumers seeking specific content IDs. Routed opportunistically using **Epidemic** multi-hop dissemination.
2. **Data Packets (`queryResponse`)**: Produced by legitimate Producers or answered from local Content Stores. Routed back toward requesters using **Spray-and-Wait** multi-copy forwarding.
3. **Content Store**: Built using [`applications/LRUCache.java`](applications/LRUCache.java), managing dynamic opportunistic caching alongside pre-configured static caches.

## Threat Models & Attacks Simulated

| Attack Module | Target Component | Mechanism | Objective |
| :--- | :--- | :--- | :--- |
| **Cache Poisoning**<br>([`CachePoisoningApplication.java`](applications/CachePoisoningApplication.java)) | Opportunistic Content Store (CS) | Injects forged Data messages (`queryResponse`) for legitimate numeric content IDs without requiring prior Interests. | Overwrite valid cached content; induce relay nodes and consumers to cache and serve corrupt data. |
| **Interest Flooding (IFA)**<br>([`InterestFloodingApplication.java`](applications/InterestFloodingApplication.java)) | Pending Interest Table (PIT) & Buffers | Generates high-rate streams of unresolvable Interests for non-existent content ranges (`1000000-9999999`). | Exhaust router PIT capacity, monopolize DTN contact durations, and evict legitimate packets. |

## Defense Mechanism: BPSec-Inspired CCN Integrity

Implemented in [`applications/CCNSecurity.java`](applications/CCNSecurity.java), this module adapts the **BIB-HMAC-SHA2 concept** from BPSec (RFC 9172/9173) to CCN message validation:

* **Canonical Tag Computation**: Generates an HMAC-SHA256 signature across the message tuple:  
  $$\text{Tag} = \text{HMAC-SHA256}(K, (\text{type} \parallel \text{queryMsg} \parallel \text{content} \parallel \text{securitySource} \parallel \text{creationTime}))$$
* **Anti-Replay Verification**: Verifies packet freshness against a sliding window and tracks highest seen sequence timestamps to prevent replay of captured legitimate responses.
* **Configurable Security Policies**:
  * **`policy = 1` (Compatibility Mode)**: Verifies tags; logs violations and invalid data without dropping packets.
  * **`policy = 2` (Enforced Mode)**: Drops unauthenticated, tampered, or replayed packets before they enter the Content Store or get forwarded.

## Empirical Simulation Results

The following table summarizes empirical metrics obtained across multiple mobility seeds (13, 27, 41) for a 12-hour simulation scenario (43,200s) on the Helsinki city map:

| Metric | Scenario Baseline<br>*(No Attack)* | Undefended<br>*(Under Attack)* | Enforced Security<br>*(Policy = 2)* | Compatible Mode<br>*(Policy = 1)* |
| :--- | :---: | :---: | :---: | :---: |
| **Attack Traffic Injected** | 0 | 245,766 | 245,766 | 245,766 |
| **Forged Data Cached (Opportunistic)** | 0 | **69,174** | **0 (Blocked)** | 69,174 |
| **Poisoned Cache Entries (Avg)** | 0.0 | **142.96** | **0.0 (Clean)** | 142.96 |
| **Poisoned Responses Delivered to Consumers** | 0 | **125** | **0 (Zero)** | 125 |
| **Legitimate Content Delivery Latency** | ~5,571 s | **~10,505 s** | **~5,419 s** | ~10,505 s |
| **Legitimate Cache Hits** | ~482 | 482 | **483** | 482 |
| **Corrupt / Missing Integrity Drops** | 0 | 0 | **69,392** | 0 (Logged) |
| **Replay Attacks Detected & Dropped** | 0 | 0 | **51** | 0 (Logged) |

> **Key Finding**: In the undefended scenario, cache poisoning corrupted ~97% of the opportunistic cache space, doubling overall query latency. Enforced BPSec integrity completely prevented corrupt cache entries (`0.0`), stopped all poisoned deliveries to consumers, and recovered baseline latency performance.

## Project Structure

```
.
├── applications/               # CCN application logic, attacks, and security helpers
│   ├── CCN_application.java    # Core CCN protocol (Producer, Consumer, Relay, PIT, Cache)
│   ├── CCNSecurity.java        # BPSec-inspired HMAC-SHA256 authentication engine
│   ├── CachePoisoningApplication.java # Cache / Content Poisoning attack generator
│   ├── InterestFloodingApplication.java # Interest Flooding Attack (IFA) generator
│   └── LRUCache.java           # Least Recently Used (LRU) Content Store cache
├── core/                       # The ONE simulation core (DTNHost, Message, SimClock)
├── movement/                   # Mobility models (WorkingDayMovement, MapBased, RWP)
├── routing/                    # Router implementations (CCNRouter, EPpSWRouter, SprayAndWait)
├── report/                     # Metric reporting engines
│   ├── CachePoisoningReporter.java
│   ├── CCNSecurityReporter.java
│   ├── CCN_application_reporter.java
│   └── MessageStatsReport.java
├── reports/                    # Pre-generated simulation outputs (.txt)
├── wdm_settings/               # Working Day Movement configuration profiles
├── tools/                      # Analysis & plotting scripts (get-metric.py, draw.sh)
├── RUITool/                    # CSV extraction and report aggregation tools
├── lib/                        # Required dependencies (DTNConsoleConnection.jar, ECLA.jar)
├── compile.bat / compileApp.sh # Build scripts for Windows and Linux/macOS
└── one.bat / one.sh            # Run scripts for Windows and Linux/macOS
```

## Prerequisites & Installation

### Requirements
* **Java Development Kit (JDK)**: Java 8 or newer (tested and verified on **OpenJDK 25 LTS**).
* **Python**: Python 3.x (for report parsing and analysis scripts).

### 1. Build the Simulator

* **Windows**:
  ```cmd
  compile.bat
  ```

* **Linux / macOS**:
  ```bash
  sh compileApp.sh
  ```

---

## Running Simulations

### GUI Mode (Interactive Visualizer)
```cmd
# Windows
one.bat default_settings.txt

# Linux / macOS
sh one.sh default_settings.txt
```

### Headless Batch Mode
To run headless batch simulations with multiple runs/seeds:
```cmd
# Run Scenario A (Baseline)
one.bat -b 1 default_settings.txt CCN_scenario_A_baseline.txt

# Run Full BPSec Security Evaluation (4 Profiles x 3 Seeds = 12 Runs)
one.bat -b 12 default_settings.txt CCNSEC_scenario_ALL.txt

# Run Replay Defense Evaluation
one.bat -b 6 default_settings.txt CCNSEC_scenario_replay.txt
```

python tools/get-metric.py <bundle_folder>
